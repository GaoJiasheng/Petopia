# S1｜守护者每日暖灯（1.0 范围）

## 背景与动机

当前 `support_benefits.dart:30` 是 `lanternActive = guardian || lanternUntil > now`——守护者的暖灯永久常亮，导致 $2.99「点亮一盏暖灯」对守护者**买了完全没有任何可见变化**（`support_yard_screen.dart:316` 的 `owned` 只对守护者商品本身计算，暖灯卡片仍可购买）。这既是体验问题也是审核风险。

改法不是把卡片禁用，而是**把它变成每日馈赠**：守护者每天可以免费点亮一盏暖灯（24 小时）。同一张卡片从"商品"变成"今天的礼物"。

> 时机说明：目前尚无任何守护者用户，所以现在改是零成本；上线后再改等于缩减已售权益，因此必须在 1.0 完成。

## 功能定义

1. 守护者身份下，`lanternActive` **不再无条件为 true**，改为与普通用户同样看 `lanternUntil`。
2. 守护者每个自然日（**设备本地时区午夜**为界）可执行一次「点亮今天的暖灯」，效果等同于购买一次暖灯：`lanternUntil = extend(lanternUntil)`（复用现有 `extend` 逻辑，从当前到期时间叠加 24 小时）。
3. 支持页的暖灯卡片按身份分叉：
   - **非守护者**：保持现状（$2.99 购买）。
   - **守护者·今日未点**：卡片标题区显示为馈赠语气（如「今天的暖灯」），按钮为「免费点亮」，**不出现价格、不走 StoreKit**。
   - **守护者·今日已点**：按钮置为「今天已经点亮」不可用态，并显示剩余时长（可复用现有到期展示方式）。
4. 存档：`SupportBenefits` 增加 `DateTime? lastFreeLanternAt`（仅此一个字段）。序列化/反序列化与现有日期字段同风格。**判断"今天是否已点"用本地日历日比较，不要用 24 小时差值**，否则跨时区/夏令时会漂移。

## 零焦虑红线（硬性，违反即返工）

产品定位承诺"通知不发送连续登录、催促回来或倒计时提醒"，本功能必须严格遵守：

- ❌ 不得为未点亮的暖灯发送任何本地通知
- ❌ 不得有连续点亮天数 / streak / 打卡计数
- ❌ 不得在主界面、菜单入口、设置项上出现红点、角标或倒计时
- ❌ 漏点一天不得有任何提示、补偿弹窗或"错过了"字样
- ✅ 文案语气是「今天也可以点一盏」，不是「别忘了点灯」
- 简言之：**只有玩家自己走到支持页时才会看见它，其余时刻它不存在。**

## 文案改动（中/英/繁三语同步）

`lib/l10n/` 三套文案表都要同步，新增串遵循相邻条目语气：
- 卡片标题、按钮三态（免费点亮 / 今天已经点亮 / 剩余时长）
- 守护者介绍区（`_SupportIntro`）：「永久点亮守护灯」→ 改为体现"每天可以点亮一盏"的说法
- 感谢文案（`thankYou`）：免费点亮不应复用付费的感谢语，另写一条更轻的

## ASC / StoreKit 同步（提审前必做，容易漏）

守护者商品的描述当前写的是"永久点亮守护灯"，机制变了必须同步，否则构成商品描述与实际不符：
- `ios/Runner/PetopiaSupport.storekit:78` 的中文 description
- `docs/app-store/support-iap.md` 的商品表与回礼表
- **App Store Connect 后台**该商品的中/英/繁三语本地化描述（这步需要账号持有人操作，Codex 只需在完成报告里明确列出"需人工更新 ASC 商品描述"并给出建议文案）

# S2｜礼物自主拆开 + 手绘开礼动画（v1.1，本单只交设计与资产）

## 动机

现在三个消耗型商品的计时**从购买瞬间开始**：睡前买的点心醒来只剩十几小时，出行前买的花篮一半花期浪费在路上。改为"礼物先送到院子，玩家想拆时再拆"，既零浪费，也把一次交易变成一个温柔时刻。

## 本单交付范围（**不实装**）

1. **数据模型设计稿**（写进本文档末尾或独立设计稿，不改代码）：`SupportBenefits` 需要新增"已拥有未拆"计数（如 `int pendingTreat/pendingLantern/pendingBouquet`），购买时 +1、拆开时 -1 并起算时长；`_schemaVersion` 由 3 升 4，需写迁移（旧档三项计数视为 0）。
2. **开礼动画序列帧资产**（本单的美术主任务，见下）。
3. **交互设计稿**：礼物在院子/手账中的呈现位置、拆开入口、动画播放后的落位。

## 🎨 动画质量硬要求（本单最重要的一条）

**必须是手绘水彩序列帧，走项目既有的精灵动画管线；严禁用代码几何图形堆砌。**

明确禁止：用 `Container`/`CustomPainter`/`AnimatedContainer` 画圆点当彩屑、用色块矩形当礼物盒、用缩放旋转的几何形状假装动画、用纯代码粒子系统。这类做法与全项目手绘水彩基调冲突，一眼廉价。

必须遵循：

- **格式**：横向序列帧条 **4096×512 = 8 帧 × 512×512**，无损 WebP，透明底——与现有宠物动作条（如 `assets/runtime/pets/cat/actions/pet_cat_var01_stageC_eat.webp`）完全一致的规格，直接用现成的 `SpriteSheetPlayer`（`frameCount: 8`，非循环，`playDuration` 控速）播放，**不需要写任何新的动画渲染代码**。
- **画风**：对齐 `assets/art/samples/` Golden Set 与现有 `assets/runtime/support/` 五张支持素材（点心/暖灯/花篮/徽章/明信片）的完成度——奶油卡通水彩、圆钝可爱、成品渲染、柔和描边、通透上色。禁止扁平 SVG 感、AI 塑料感、脏笔触。
- **构图**：遵循美术规格 §0.2——主体完整不触边、四周 ≥10% 安全边距、主体长边占画布 78–82%、8 帧间主体尺寸与基线稳定（沿用 `tools/check_pet_art.py` 的帧稳定阈值自检）。
- **三条动作弧线**（各一条，共 3 个序列帧条）：
  - `support_open_treat`：系着布结的小食盒 → 结松开 → 盒盖轻掀、暖光溢出 → 点心显形、几片水彩质感的花瓣/星屑飘散 → 定格
  - `support_open_lantern`：未点亮的灯 → 灯芯亮起一点 → 光晕由内向外晕开（水彩晕染质感，不是发光圆形） → 暖光稳定 → 定格
  - `support_open_bouquet`：牛皮纸包裹的花束 → 纸包展开 → 花朵依次舒展 → 完全绽放、一两片花瓣落下 → 定格
- **收尾帧**：第 8 帧必须与该礼物在院子里的静态素材（`support_treat.webp` 等）姿态、尺寸、光照一致，动画结束切静态时不得跳变。

**交付物**：3 条序列帧条 + 每条一张 8 帧接触表（`assets/art/qa/support-open/`）证明帧间连贯、无残片、无跳变。
