# 院子排布截图分析与建议 · 2026-09-14

建议方向：**中央宠物 + 两侧生活角 + 稳定的来客位置**。先统一比例和前后关系，再修订静态锚点。日常手机院子已有亲近感，可以保留；满摆件和平板的构图更需要调整。

本轮只做现状截图、代码核对和方案，没有修改院子产品代码、资源或测试，也没有完成或提交后续工单。当前提交为 `1e6f605`，版本 `1.0.1+41`；院子代码含已完成的 T0a/T0b，T1/T2/T3 尚未实施。

## 一、截图里具体哪里怪

### 1. 满摆件像沿边摆开的陈列品，缺少生活场景的组合关系

草地满摆件图中，左侧灯、花箱、炉子，右侧风铃、蘑菇凳、风向标，仍形成两条纵向排列。虽有纵向错位，物件的横向位置都偏边缘。后排书架和极小的池塘独立放在中间，没能与左右物件组成一个小景。

视觉上先看到的是“一件件摆设”，随后才看到“宠物生活的院子”。八个槽位都可见是必要条件，但并不能单独保证整体构图自然。

**建议：** 保留八个槽位及玩家选择；静态锚点形成左右两个疏密有别的小景：0/2/6 与 1/3/7 有前后和内外关系，4/5 保留前景位置。中央留连续草地，沿背景入口通向宠物。示意图只表达空间关系，精确尺寸需用最高摆件组合验证，不对槽位新增物品类别限制。

### 2. 池塘比食盆还小，物件比例失去语义

同一张满摆件图里，后排池塘像一粒蓝色装饰石；右前风向标却接近或超过宠物高度。按现有裁切与渲染公式计算：

| 满摆件场景的可见尺寸 | iPhone 6.9 竖 | iPad 13 竖 |
| --- | ---: | ---: |
| 小池塘宽度 | 22.8pt | 43.2pt |
| 食盆宽度 | 43.1pt | 93.9pt |
| 池塘 / 食盆宽度 | 0.53 | 0.46 |
| 风向标高度 | 146.7pt | 284.5pt |
| 当前 B 阶橘猫静态可见高度参考 | 149.1pt | 227.3pt |

数值是代码和资源 alpha 边界推导，不是对动画截图逐帧的精确量测。详见 `build/yard-layout-review-2026-09-14/layout-metrics.json`。猫参考图的可见高度占方形画布 404/512。

成因：玩家摆件统一走高度尺寸；池塘使用 `0.39` 高度倍率，又乘后排 `0.78` 透视倍率，得到过小的地面面积。风向标使用 `1.71` 高度倍率，并位于前景放大段。

**建议：** 高立件按高度定标，池塘、花坛等地面景物按可见地面宽度定标。池塘可先以食盆宽度的约 1.3–1.6 倍试排，最终大小由后排容量决定。不要直接放大所有摆件；风向标与炉子也要和中央宠物一起复核主次。

### 3. 来客被避让算法推到前景，大小却仍按较远的配角处理

手机满摆件双角色图中，小鹿和回访兔站到了食盆之后、更靠近动作栏的前景，体型却显著小于橘猫。iPad 同场景里它们又位于宠物侧后方。跨设备的空间关系不稳定。

T0 的避让成功消除了矩形重叠，但当前算法先向下找空隙、再内收，拥挤时继续缩小角色；几何安全与视觉景深仍是两件需要分别验收的事。

**建议：** 左右各预留一个明确的侧后方落脚区，来客与回访共存时各用一侧。先为这些位置留空间，再围绕它们排静态摆件；正常满摆件场景不要依赖不断缩小角色来塞缝。哺乳类来客、回访伙伴可先以主宠可见高度的约 60%–75% 试排；微小昆虫单独保留可辨认的下限，不强行与鹿等高。到访时不得移动、隐藏或替换玩家摆件。

### 4. iPad 的宠物、摆件、碗采用不同的放大节奏

iPhone 宠物方形画布为 189pt，iPad 13 为 288pt，只增加约 52%；场景比例从 1.048 提高到 2.35。各档锚点虽作了补偿，满摆件风向标仍从 146.7pt 增至 284.5pt，增加约 94%。日常 iPad 图中食盆也显得偏大，宠物与整片草地的联系较弱。

**建议：** 手机宠物大小先保持。iPad 宠物可试放大约 15%–20%，并以宠物脚下的照料区域为参照，重新协调碗、来客与周围摆件。碗的位置以脚下区域为参照，避免仅靠全屏百分比而在某档设备上显得分离或盖住脚。

### 5. 背景镜头与锚点还没有共用地面参照

手机日常图的留白有放松感；iPad 使用手机母图 cover 后，镜头更近、两侧建筑与植被更大，同一套百分比位置落在不同的景深上。直接继续微调 y 值，容易一个主题合适、换主题又不自然。

**建议：** 先处理 T3 的平板背景取图，复核十二主题的可用草地，再定摆放范围。布局用“可用草地上沿—实际动作栏上沿”定义地面区域，里面安排远景、角色和前景。共用尺寸规则和每个主题的地面参照；不依赖自动识图决定玩家摆放，不统一添加可能与原画底座重复的椭圆阴影。

## 二、推荐方案

![空间关系示意](/Users/gavin/work/petopia/build/yard-layout-review-2026-09-14/layout-proposal.png)

上图是布局示意，**不是已经实现的游戏效果图**；数字表示现有槽位，没有新增可玩区域或道具。

- **后景：** 保留主题建筑、入口、围栏。后排 6/7 与左右摆件构成小景，豪华树和池塘只在玩家未占用的后排位置显示。
- **中景：** 宠物是最先被看到的角色，来客与回访在两侧略后。角色脚底、尺寸与遮挡顺序表达相同的远近关系。
- **前景：** 碗靠近宠物照料区，4/5 与动作栏之间保留缓冲；完整八槽场景也保留中央连续草地。
- **尺寸：** 用可见主体而非透明方框衡量大小，地面景物与高立件采用各自适合的尺寸指标；手机、平板、横屏有独立画布约束。

首轮建议先做草地主题的 iPhone 6.9 / 17e 与 iPad 13 三档静态样板：日常、八槽满摆件、八槽双来客。先确认“池塘看得清、猫仍是主角、来客没有落在更近却更小的位置”，再扩到 mini、横屏和十二主题。

这轮整体方案会涉及超出原 T0 批准范围的静态锚点与尺寸重排，应作为后续单独的视觉实现范围；本轮分析不等同于已经执行这些变更。已经验证的 T0 防重叠逻辑仍保留到替代方案通过验证。

## 三、实施顺序与验收

建议在恢复剩余工单实现前，先确认本轮构图方向；原 T0–T9 的提交记录不改写。

1. **校准截图与地面：** 修正此前发现的横屏画布 / MediaQuery 尺寸不同步问题，落实 T3 平板背景选择，取得可用地面范围。
2. **建立样板：** 统一宠物、来客、碗和各类摆件的比例；安排八槽与两处角色落脚区。用现有美术先验证，无需先重画资源。
3. **扩展适配：** 完成 T1 横屏锚点，随后接入 T2 后排豪华反馈；以同一套构图约束复核各主题。
4. **回归：** `flutter analyze` 0 issue、`flutter test` 全绿；完整 placements 4 竖 + 2 横全绿，并按约定执行发布门禁。不得改弱 oracle。

新增人工视觉验收项：

- 缩略图首先能辨认当前宠物；池塘、书架与风铃都能辨认。
- 高摆件不会在多个设备上同时成为最抢眼的主体。
- 来客 / 回访到访前后玩家摆件矩形完全不变；临时角色仍处于明确的景深层。
- 稀疏和八槽满摆件都自然；最高摆件组合仍不重叠、不盖动作栏。
- 横屏同时核对截图像素和页面实际逻辑尺寸，iPad 13 为 2752×2064 / 1376×1032，mini 为 2266×1488 / 1133×744。
