# Petopia 双语文案语气基线

本文档约束 App 内中文、英文、动态叙事、付费页和 App Store 文案。目标不是把每句话都写得可爱，而是让整个作品始终温暖、自然、克制，并且值得长期阅读。

## 1. 核心语气

- **温暖，但不索取回应。** 可以表达陪伴和想念，不暗示玩家必须回来、付费或维持连续登录。
- **可爱，但不幼稚。** 可爱来自具体动作、观察和角色性格，不依赖叠词、语气词、全大写或连续感叹号。
- **诗意，但不堆砌。** 一段文案只保留一个清晰意象；系统状态优先准确，叙事内容再使用留白。
- **亲近，但不越界。** 宠物可以记得玩家和院子，不把玩家写成宠物唯一的情绪支点。
- **轻松，但不含糊。** 购买、存档、隐私、错误和恢复状态必须直接说明发生了什么。

## 2. 中文标准

- 系统标题和按钮使用明确动词，如“完成”“恢复购买”“暖绒不足”，避免“记住啦”“买不起”等口语化或带评判的表达。
- “小、轻轻、慢慢、悄悄、软软、暖暖”等词只在动作确有画面价值时使用，同一句不重复堆叠。
- 叙事正文不使用 `TA`、规格编号、`Lv`、`+1`、`系统自动` 等跳出世界观的表达；等级与奖励只在结构化 UI 中展示。
- 不以“每天等你回来”“很想很想的人”“除非你肯等”等句式制造责任感。
- 角色笑点保持具体、短促，不用网络流行语、过量括号或连续感叹号支撑语气。

## 3. English Standards

- Prefer natural, compact English over line-by-line literal translation.
- Use sentence case. Avoid all caps, repeated exclamation marks, and stacked intensifiers.
- Do not lean on *little*, *tiny*, *soft*, *gentle*, or *quietly* as default cozy adjectives. Keep them only when size, texture, or manner matters.
- Let personality come from choices and observations, not exaggerated baby talk or emotional dependence.
- Use consistent canonical names for every pet, visitor, place, item, and entitlement.
- Keep transactional and privacy copy factual: action, outcome, duration, restore behavior, and next step.

## 4. 付费文案

- 明确说明支持完全自愿，且不会改变成长、货币、冷却、稀有度或可玩内容。
- 临时回礼必须写清持续时间；永久回礼必须写清可恢复范围。
- 不使用限时、错失、倒计时、稀缺性、比较或身份优越感推动购买。
- 不把“不购买”写成没有爱心，也不把购买写成宠物得到照顾、回家有路或院子继续存在的前提。
- 成功页只表达感谢和已解锁内容，不要求玩家继续回来或再次支持。

## 5. 叙事文案

- 事件正文只写发生了什么；经验、线索、图鉴进度和相册写入由结果 UI 展示。
- 明信片可以想念院子，但不得暗示玩家必须回信、上线或持续等待。
- 活力角色可以兴奋，但每段最多一个感叹号；高冷角色可以含蓄，但不刻薄。
- 通用事件避免只适用于猫狗的声音或身体动作；物种限定内容必须由条件约束。
- 固定 UI 与系统状态必须事实一致。组合式叙事允许中英文独立写作，但必须使用同一地点、遭遇、插曲与性格，并保持相同的情绪强度和角色态度。

## 6. 发布前检查

1. 这句话是否准确说明当前状态？
2. 删掉一个“小、轻轻、little、tiny”后是否更自然？
3. 玩家离开或不付费时，这句话是否仍然尊重玩家？
4. 英文是否像母语表达，而不是中文句式换词？
5. 文案是否包含规格、奖励数值或内部实现痕迹？
6. 同一名称在 UI、叙事、商店和支持页面是否完全一致？
